Implementation Log
==================

Current architecture
--------------------

- Arrow is the connector-target contract: connectors emit
  `pyarrow.RecordBatchReader` and targets consume it.
- Public runtime concepts are Connector, Cursor, Arrow stream, Target, and
  MergeConfiguration. There is no pipeline, source, resource, registry, or
  state-manager abstraction.
- `demo.py` is a thin YAML/configuration adapter. Concrete implementations
  live in `ingester.connectors` and `ingester.targets`; package facades
  preserve their public imports.
- The project requires Python 3.12+ and CI tests Python 3.12 and 3.15.
- Dependencies are uv-managed. CI runs locked synchronization, Ruff lint and
  format checks, and pytest.

Implemented connectors
----------------------

- RestConnector supports JSON record selection, strict declared-schema
  projection, fixed-size Arrow batches, static string headers and query
  parameters, bearer tokens from named environment variables using the
  standard `Bearer` authorization scheme, offset
  pagination, and bounded timeout/retry/backoff behavior.
- REST retries only transport failures and 429/5xx responses; configuration,
  schema, response-shape, and other HTTP failures fail immediately.
- ParquetConnector exposes local Parquet files as native Arrow batch streams.

Implemented targets and merge behavior
--------------------------------------

- ParquetTarget and DuckDBTarget support `replace`, `append`, `upsert`, and
  `scd2`.
- All single-file Parquet destination writes use temporary files and atomic
  replacement. Append rewrites existing and incoming batches because Parquet
  does not support safe in-place append.
- DuckDB upsert and SCD2 mutations are transactional. Failed database writes
  roll back before matching destination rows can be lost.
- Scalar `merge: replace` and `merge: append` remain valid. Upsert uses
  `merge: {strategy: upsert, keys: [...]}`.
- Upsert requires source/destination schema compatibility and non-null,
  unique incoming key tuples. It replaces matching destination rows and
  retains unmatched rows.
- SCD2 requires business keys, tracked fields, an `int64` source
  `effective_at` field, and explicitly named `valid_from`, `valid_to`, and
  `is_current` output fields. It closes changed current rows at the source
  effective value and creates a new current version. Unchanged tracked fields
  do not create history.

Incremental loading and state
-----------------------------

- The implemented cursor is a destination-derived REST high watermark over a
  declared `int64` field. Targets derive its maximum persisted value; the
  first load is unfiltered.
- High-watermark cursors are compatible with append, upsert, and SCD2.
- State is derived from destination data; no hidden ingestion metadata
  columns or state store exists.
- The design allows opaque source cursors later, but no persistence mechanism
  has been implemented.

Important constraints and deferred behavior
-------------------------------------------

- REST responses are still JSON-decoded before Arrow batches are formed.
- Supported REST authentication is bearer tokens only. OAuth refresh, API
  keys, Basic auth, mTLS, custom signing, and secret-provider integration are
  not implemented.
- REST pagination is offset-based only. Cursor/next-link pagination and rate
  limiting are not implemented.
- Strict schema policy is the only REST schema policy. Supported declared
  primitive Arrow types are int64, float64, string, and bool.
- Parquet inputs are local files only. Object storage, partition discovery,
  flat-file connectors, ADBC connectors, and connector registries are not
  implemented.
- Upsert does not provide schema evolution, deletion synchronization, or an
  implicit duplicate-record ordering rule.
- SCD2 does not support timestamps, multiple events for one key in a load,
  deletion/tombstone semantics, schema evolution, source-order repair, or
  opaque cursors.

Validation baseline
-------------------

- The latest full suite passed: 51 pytest tests.
- Repository checks passed: `uv run ruff check .` and `git diff --check`.
- Tests cover connector configuration and retry behavior, native Parquet
  streaming, target batching, all implemented merge strategies, cursor

Documentation and typing update
-------------------------------

- Added a public README covering installation, command-line usage, supported
  configuration, merge behavior, and the package API.
- Added Google-style public API docstrings. Docstring sections describe
  behavior without repeating inline type annotations.
- Added missing constant annotations for connector Arrow type mappings and
  batch sizes.
- Corrected REST bearer authentication to send the configured token with the
  `Bearer` authorization scheme; focused tests verify the outgoing header.

This iteration adds no connectors, targets, cursor modes, merge semantics,
transformations, or runtime abstractions. It improves public documentation,
type clarity, and the reliability of the existing bearer-authentication
capability.
