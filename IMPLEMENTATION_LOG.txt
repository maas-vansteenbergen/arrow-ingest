Abstraction surface check
-------------------------
- Public concepts introduced: Connector, Target, and the Arrow
  RecordBatchReader contract.
- Concrete implementations introduced: RestConnector and ParquetTarget.
- No source/resource/pipeline/asset/dataset/block/flow abstraction exists.
- The `connector` and `target` YAML sections are configuration, not runtime
  framework concepts.

Design decision: initial connector scope
----------------------------------------
- Added initial supported connector categories to DESIGN_PLAN.txt: Parquet,
  flat files, ADBC-capable databases, and HTTP APIs.
- Recorded that object storage is a file location rather than a separate
  connector category.
- Explicitly excluded message queues/streams, CDC/replication protocols,
  spreadsheets, and SDK-only integrations from the initial scope.
- This bounds the project around connectors that can reasonably emit Arrow
  batches without introducing a separate streaming or replication framework.

Strict schema policy implementation completed
---------------------------------------------
- Added `schema_policy: strict`, which is also the default when omitted.
- Strict is a projection policy: every declared field is required and must
  match its declared primitive Arrow type; undeclared source fields are
  ignored.
- Null remains valid only for nullable Arrow fields.
- Rejected unsupported policies rather than silently falling back.
- Added tests for nullable fields, missing declared fields, undeclared source
  fields, type mismatches, and unsupported policy names.

Append merge strategy implementation completed
----------------------------------------------
- Added `append` alongside `replace` as a supported MergeStrategy.
- DuckDBTarget appends incoming Arrow streams with `INSERT INTO` when the
  configured table exists, and creates the table from the stream otherwise.
- ParquetTarget appends without materializing either dataset: it streams the
  existing file's batches followed by the incoming batches into a temporary
  Parquet file, then atomically replaces the destination.
- Parquet append requires an exactly matching Arrow schema and leaves the
  existing output intact when the new stream is incompatible.
- `load()` reports only the number of rows written by the current append,
  rather than the destination's total number of rows.
- Added coverage for merge-strategy parsing, Parquet append and schema
  rejection, and DuckDB append.
- Not implemented: primary-key-aware upsert, SCD2, destination metadata, or
  schema evolution.

Destination-derived cursor implementation completed
---------------------------------------------------
- Added Cursor as the small runtime value carrying an integer destination
  field and its maximum persisted value.
- Added the first REST incremental mode: `cursor.type: high_watermark`, with
  a declared `int64` schema field and a source request parameter.
- Before a configured append load, the CLI asks the target for the maximum
  persisted cursor value. REST sends that value only when one exists, so the
  first load remains unfiltered.
- ParquetTarget derives the value by scanning the configured output column;
  DuckDBTarget derives it with `max()` from the configured table.
- Restricted this cursor mode to append and upsert loads. It does not introduce
  a state store, hidden metadata columns, opaque cursor persistence,
  timestamps, compound cursors, lookback windows, or duplicate handling for
  tied values.
- Added coverage for REST cursor parameters and validation, both target
  implementations, first-run behavior, and the append-only requirement.

Upsert merge strategy implementation completed
-----------------------------------------------
- Added structured merge configuration. Existing scalar `append` and
  `replace` configuration remains valid; upsert requires:
  `merge: {strategy: upsert, keys: [...]}`.
- Added MergeConfiguration, which validates strategy/key combinations for
  both parsed configuration and direct library callers.
- DuckDBTarget stages the incoming Arrow stream, rejects null or duplicate
  key tuples, validates schema compatibility, then replaces matching rows and
  inserts incoming rows in a transaction.
- ParquetTarget stages incoming batches, applies the same key validation,
  creates the merged output through DuckDB, and atomically replaces the
  destination file.
- Both targets initialize a missing destination from the incoming stream and
  report the number of incoming rows written by an upsert.
- Destination-derived high-watermark cursors are compatible with upsert as
  well as append loads.
- Source and destination schemas must match exactly. No implicit duplicate
  ordering, null-key behavior, schema evolution, deletion synchronization, or
  SCD2 history behavior was added.
- Added coverage for merge parsing, single and composite key replacement,
  null and duplicate source keys, and schema mismatch rejection for both
  targets.
